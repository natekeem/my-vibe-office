# 에이전트 작업 가이드

Codex, Claude Code, OpenCode, Roo Code와 사람이 같은 방식으로 이 저장소를 변경하기 위한 절차다.

## 작업 시작

1. `git status --short --branch`로 기존 변경을 확인하고 사용자 변경을 덮어쓰지 않는다.
2. `AGENTS.md`, `docs/HANDOFF.md`, 작업에 해당하는 정본을 읽는다.
3. `git log -5 --oneline`으로 최근 완료 흐름을 확인한다.
4. 검색은 `rg`와 `rg --files`를 우선 사용한다.
5. 현재 구현과 테스트로 요구사항을 확인하고 추측을 문서화된 사실처럼 쓰지 않는다.

## 작업 범위 선언

구현 전에 다음을 짧게 정리한다.

- 바꾸는 사용자 동작 또는 문서 목적
- 영향을 받는 모듈과 데이터 계약
- 유지해야 할 불변 조건
- 완료를 증명할 검사
- 명시적으로 다루지 않는 범위

로드맵의 다음 버전은 사용자가 재개하지 않았다면 자동으로 시작하지 않는다.

## 구현 규칙

- Node.js ESM을 유지하고 서버는 외부 런타임 의존성 없이 동작하게 한다.
- CLI 실행은 `shell:false`와 인자 배열을 유지한다.
- repo 밖의 파일과 비밀값은 변경하지 않는다.
- 로컬과 Web Hub 사이의 데이터 이동은 `PRODUCT_SURFACES.md` 경계를 따른다.
- UI 상태를 추가하면 저장 모델, API, 화면, 문서, 테스트의 영향을 함께 확인한다.
- 새 문서보다 기존 정본 갱신을 우선한다.

## 검증

```powershell
npm run check
npm test
npm run docs:check
```

UI를 바꿨다면 로컬 서버에서 해당 화면, 빈 상태, 작은 창, 설정 저장 후 재로딩을 확인한다. portable 릴리스가 필요한 변경은 마지막에 `npm run dist`를 실행한다.

## 세션 종료와 인수인계

코드 변경 여부와 관계없이 의미 있는 작업을 마칠 때 다음을 확인한다.

1. 관련 정본 문서가 현재 코드와 일치하는지 확인한다.
2. `docs/HANDOFF.md`에 현재 기준선, 완료 내용, 검증, 알려진 제약, 다음 시작점을 반영한다.
3. `npm run docs:check`로 링크와 금지 표현을 검사한다.
4. 작업 트리와 원격 동기화 상태를 확인한다.

`HANDOFF.md`는 일기장이 아니다. 최근 세션 대화를 복사하지 말고 다음 작업자가 의사결정에 필요한 현재 사실만 유지한다.

## 완료 보고

- 사용자에게 보이는 결과
- 변경 파일과 중요한 설계 선택
- 실행한 검사와 결과
- 실행하지 못한 검사와 이유
- 남은 위험과 다음 로드맵 항목
- 요청받은 경우에만 commit·push 정보
