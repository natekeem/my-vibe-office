# 제품 표면과 데이터 경계

## 원칙

Local Office와 Web Hub는 같은 제품군이지만 같은 신뢰 경계를 사용하지 않는다. 로컬 실행 권한과 공개 커뮤니티 기능을 한 프로세스에 넣지 않는다.

| 기능 | Windows Local Office | Web Hub |
|---|---|---|
| Git repo·worktree·branch | 소유·실행 | 공개 메타데이터 링크만 |
| Codex·Claude·OpenCode 실행 | 소유 | 실행하지 않음 |
| MCP·Skill·Plugin·Agent | 설치·적용·검증 | 탐색·배포·버전·다운로드 |
| 프롬프트·로그·diff | 로컬 기본 | 사용자가 선택한 공개본만 |
| 토큰·비용 | 원본 상세 | 동의한 집계값만 |
| 데일리 리포트 | 세션 기반 초안 생성·검토 | 승인된 글 게시·조회 |
| 대시보드 | 개인·repo·agent·model | 공개 Office 비교·랭킹 |
| 인증·계정 | 선택적 Web Hub 연결 | 게시자·다운로드·프로필 |

## Windows Local Office

- 로컬 repo와 CLI 프로세스의 유일한 실행 주체다.
- 사내 endpoint와 환경 변수 참조를 로컬에서만 해석한다.
- 사용량 원본, 작업 로그, 소스 diff를 로컬에 보관한다.
- Web Hub에서 받은 번들은 격리된 임시 위치에서 검사한 뒤 명시적으로 설치한다.
- 게시 작업은 항상 `초안 → 포함 데이터 미리보기 → 사용자 승인 → 전송` 순서다.

## Web Hub

- MCP, Skill, Plugin, Agent, Workflow Pack을 공통 패키지로 제공한다.
- 패키지 페이지에는 작성자, 버전, 호환 도구, 요구 권한, 라이선스, 해시, 검증 결과를 표시한다.
- 공개 데일리 리포트와 게시판은 소스·내부 경로·비밀정보를 받지 않는다.
- 리더보드는 기간과 규모를 정규화하고 원본 토큰 수치와 게임형 점수를 구분한다.
- `시가총액` 대신 실제 금융 가치로 오해되지 않는 `Office Score` 명칭을 기본으로 사용한다.

## 공유 계약

초기 공유 단위는 JSON manifest와 압축 번들이다.

```json
{
  "schemaVersion": 1,
  "kind": "skill",
  "id": "publisher/package-name",
  "version": "1.0.0",
  "compatibility": ["codex", "claude", "opencode", "roo"],
  "permissions": ["read:repo"],
  "files": [{ "path": "SKILL.md", "sha256": "..." }]
}
```

로컬 앱은 알 수 없는 `schemaVersion`, 절대 경로, 상위 경로 이동, 실행 파일, 선언되지 않은 권한을 기본 거부한다.

## 데일리 리포트 공개 흐름

1. 해당 날짜의 로컬 세션과 Git 메타데이터를 선택한다.
2. 로컬 에이전트가 목표, 결정, 변경, 검증, 배운 점을 블로그 초안으로 요약한다.
3. 비밀값, 절대 경로, 내부 URL, 원문 프롬프트를 로컬에서 제거한다.
4. 사용자가 공개 미리보기를 편집하고 승인한다.
5. Web Hub는 승인된 Markdown과 공개 집계값만 받는다.

## 아직 공유하지 않는 데이터

- 전체 프롬프트와 모델 응답 원문
- 소스 코드와 미커밋 diff
- 환경 변수, 인증 토큰, 사내 endpoint
- 로컬 절대 경로와 사용자 이름
- 공개 동의를 받지 않은 토큰·비용·직원 정보
