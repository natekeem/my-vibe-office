## 권장 멀티 에이전트 운영법

1. repo마다 PM 또는 테크리드를 마스터로 지정한다.
2. 인계 순서는 `PM → 개발자 → 디자이너 → QA`처럼 완료물을 검증하는 방향으로 둔다.
3. 동일 경로를 공유하면 `shared-serial`을 사용한다. 실행은 직렬이지만 계획과 결과가 자동 인계된다.
4. 실제 병렬 구현이 필요하면 에이전트마다 별도 Git worktree와 브랜치를 만들고 파일 소유 영역을 나눈다.
5. 통합은 마스터가 한 브랜치씩 가져와 테스트한 뒤 진행한다. 겹치는 파일은 자동 병합보다 재배정을 우선한다.

## 현재 안전 보장과 경계

- 정규화된 작업 경로를 실행 자원 키로 사용하며 같은 키의 프로세스는 겹치지 않는다.
- 서로 다른 repo 또는 서로 다른 worktree 경로는 설정된 동시 실행 수까지 병렬 실행할 수 있다.
- `isolated-worktrees`는 운영 전략을 기록하고 UI에 표시한다. worktree·브랜치 생성과 자동 병합은 아직 자동화하지 않는다.
- 앞 단계 프로세스가 정상 종료된 경우에만 다음 단계로 인계한다. 실패하면 미션을 검토 상태로 멈춘다.

## 다음 단계 후보

- Git worktree와 에이전트 브랜치 자동 생성·정리
- 파일 소유권 매니페스트와 변경 경로 중복 사전 감지
- 마스터 승인 게이트, 실패 재시도·백오프, 단계 재실행 UI
- 파이프라인 순서 드래그 편집과 병렬 분기·합류(DAG)
- 날짜 범위·모델·미션별 사용량 필터와 예산 경고
- 상태 내보내기·가져오기, 자동 백업과 장기 로그 회전

원본의 결제, 라이선스, 업데이트, 텔레메트리, 피드백 전송, 원격 터널 기능은 의도적으로 포함하지 않는다.
