# 제품 발견 기록과 개발 범위

이 문서는 초기 제품 설계 과정에서 정리한 기능군과 범위 판단을 보존한다. 현재 구현의 정본은 `ARCHITECTURE.md`, 현재 계획의 정본은 `ROADMAP.md`이며, 이 문서는 아이디어 누락을 방지하기 위한 보조 기록이다.

## 발견한 핵심 문제

- 여러 CLI 코딩 에이전트의 상태와 작업 결과가 도구마다 흩어진다.
- repo, 에이전트, 작업, Git 이력, 사용량을 하나의 작업 공간에서 연결하기 어렵다.
- 여러 에이전트가 같은 repo를 동시에 수정할 때 경로 충돌과 인계 누락이 생길 수 있다.
- 역할 프롬프트, 실행 어댑터, 모델, 팀 규칙이 한 설정에 섞이면 재사용과 운영이 어렵다.
- 로컬 코드와 비밀정보를 유지하면서도 필요한 공개 자산만 공유할 경계가 필요하다.

## 제품 기능군

1. Office와 Git repo 연결
2. 사용자 에이전트, 역할 프리셋, CLI 실행 프로필
3. 작업 카드와 todo/queued/running/review/done 상태
4. 팀, 리드, 라우팅, 단계별 인계
5. 프로세스 실행·중지·세션·로그·산출물
6. Git branch, history, worktree와 GitHub 작업 정보
7. MCP, Skills, Rules, Plugins, Subagents 구성 인벤토리
8. 일정, 사용량, 대시보드와 활동 기록
9. 향후 공개 카탈로그, 리포트, 마켓플레이스

## 현재 반영된 설계 원칙

- Office의 최상위 경계는 canonical local Git repo다.
- 에이전트 역할과 CLI adapter/model은 독립된 설정이다.
- 팀마다 리드, 직원, 운영 지시, 라우팅과 워크플로를 가진다.
- 직무 이름이 아니라 `modeId`와 전문 태그로 작업을 배분한다.
- 같은 repo 경로의 쓰기는 직렬화하고 실제 병렬 작업은 worktree로 격리한다.
- 로컬 실행 데이터는 기본적으로 외부로 전송하지 않는다.

## 아직 완료하지 않은 기능군

- 조건 분기와 승인 게이트가 있는 Workflow Pack 편집기
- 작업 의존성 DAG와 변경 예상 경로 충돌 검사
- 부모/자식 에이전트 실행 트리와 세션 간 역할 전환
- MCP·Skill·Rule·Plugin 편집과 설치 검증
- GitHub Projects 상태의 선택적 양방향 동기화
- Web Hub, 공개 리포트, 카탈로그, 마켓플레이스

세부 우선순위와 버전 배치는 `ROADMAP.md`를 따른다. 이 목록만 보고 구현을 시작하지 않는다.

## 범위 밖 또는 별도 승인 대상

- 사용자 승인 없는 소스, 프롬프트, diff, 로그, 비밀정보 전송
- 인증 없는 외부 네트워크 바인딩
- 결제·과금·라이선스 활성화
- 사용자 동의 없는 자동 업데이트와 텔레메트리
- 외부 메시징과 원격 터널
- 자동 병합 또는 브랜치 보호 규칙 우회

## 이 문서의 유지 규칙

- 새로운 기능군을 발견했지만 로드맵에 배치하지 않았을 때만 갱신한다.
- 현재 구현 상세를 복제하지 않는다.
- 특정 외부 제품, 설치 경로, 브랜드, 패키징 추정은 기록하지 않는다.
