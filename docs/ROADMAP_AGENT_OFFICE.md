# My Vibe Office 제품 로드맵

## 방향

Office는 Git repo에 연결된 로컬 작업 공간이고, 에이전트는 직급 순서가 아니라 **작업 모드와 전문 태그**로 선택된다. PM, FE, 디자이너, QA는 조직 표현일 뿐 고정 파이프라인이 아니다. 작은 UI 수정은 FE가 바로 처리할 수 있고, 복합 기능은 설계·구현·검증 모드를 필요한 만큼만 조합한다.

## 참고 제품에서 채택한 원칙

### AgentsRoom에서 착안

- 프로젝트를 실제 로컬 폴더에 연결하고 에이전트별 역할·터미널·모델을 구성한다.
- 사용자가 팀 흐름을 설계하며 고정 직무 순서를 강요하지 않는다.
- 세션 맥락을 유지한 역할 전환, 에이전트별 diff, 컨텍스트 상태, 스킬 라이브러리를 장기 기능으로 둔다.

### Claw Empire에서 착안

- 조직/부서 표현과 작업 보드를 실제 실행·로그·Git worktree에 연결한다.
- 공통 오케스트레이션 위에 Workflow Pack을 얹고 입력, 프롬프트, QA, 산출물 규칙을 팩별로 분리한다.
- 검토와 의사결정은 자동 실행과 분리된 명시적 게이트로 둔다.

## 현재 구현: v0.9

- `adaptive`, `manual`, `sequential` 프로젝트 라우팅
- 요청 키워드와 워크플로를 이용한 결정론적 자동 라우팅
- planner, architect, coder, debugger, frontend, backend, fullstack, design, qa, reviewer, security, devops, git, docs, research 모드
- 에이전트의 직함, 작업 모드, 전문 태그 분리
- 빠른 수정, FE 변경, BE 변경, 기능 개발, 장애 대응, 리뷰 전용 워크플로
- 적합한 전문 인력이 없을 때 마스터로 안전 폴백

## 다음 단계

### v0.10 · 워크플로 빌더와 승인 게이트

- 프로젝트별 단계 추가/삭제/조건부 분기 UI
- 단계별 완료 조건과 승인 필요 여부
- 수정 없는 리뷰, 변경 승인, 병합 승인을 별도 상태로 표시
- 라우팅 미리보기: 실행 전에 선택된 모드와 이유 확인

### v0.11 · 작업 그래프와 병렬 안전성

- 선형 pipeline을 의존성 DAG로 확장
- 변경 예상 파일 선언과 겹침 감지
- 에이전트별 worktree 자동 생성, 브랜치 수명주기, 통합 담당자 지정
- 충돌 시 자동 재시도 대신 Git·릴리스 매니저 결정함으로 전달

### v0.12 · 역할 전환과 서브에이전트 시각화

- 같은 세션의 맥락을 유지하며 planner→coder→reviewer 모드 전환
- Claude subagent/Codex/OpenCode 자식 프로세스를 ITO 인력으로 시각화
- 호출자, 위임 목표, 사용 모델, 실행 시간, 비용, 결과를 부모 에이전트 아래 표시

### v0.13 · 컨텍스트와 도구 운영

- 에이전트별 MCP, skills, rules, plugins 적용 스냅샷과 변경 이력
- 컨텍스트 사용량, 오래된 지시, 규칙 충돌, 드리프트 경고
- repo 팀 템플릿과 스킬 번들 내보내기/가져오기

### v0.14 · GitHub 양방향 운영

- Issue ↔ 작업 카드 상태 동기화
- GitHub Projects 상태 필드 매핑과 담당 에이전트 연결
- PR diff를 에이전트/작업별로 필터링하고 카드·커밋·대화를 추적
- 브랜치 보호 규칙을 존중하는 병합 승인 흐름

## 보류 경계

- 원격 터널, 외부 메시징, 자동 업데이트, 텔레메트리는 로컬 보안 모델을 바꾸므로 기본 범위에서 제외한다.
- LLM이 임의로 모든 단계를 만드는 자유 라우팅은 비용과 예측 가능성 문제가 있어, 라우팅 미리보기와 승인 게이트 이후에 검토한다.
- 참고 제품의 코드나 고유 자산을 복제하지 않고 공개된 제품 개념을 독립 구현한다.
